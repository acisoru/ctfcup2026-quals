# Художественный фильм | forensics, blockchain, evm, reverse

**Автор:** [@itsnagixyz](https://t.me/itsnagixyz)

## Описание

> «Lucky Spire» — ончейн-казино с проверяемой честностью. За сезон казино обескровили.
> Операторы свалили всё на «компрометацию горячего кошелька», аудиторы подписались под
> игровыми контрактами — и контракты действительно чистые. Но горстка никак не связанных
> игроков словила невозможные винстрики, а банк казино утёк. Восстановите, что произошло,
> и кто за этим стоит.

## Деплой

Раздатка — один `tar.gz` с архивом цепочки (файл состояния anvil). Деплой на стороне
платформы не нужен: участник сам поднимает локальную ноду из файла. Нода фиксируется на
форке **Shanghai** (pre-Cancun): трюк с метаморфным ре-деплоем работает только до Cancun,
потому что EIP-6780 ломает `selfdestruct`, на котором держится сброс nonce.

Генерация цепочки и сборка раздатки — скрипты в [deploy/](deploy/): `generate.py`
(строит цепочку на запущенной ноде), `finalize.sh` (дамп → `tar.gz` → проверка solve),
`flag.py` (считает флаг). Нода поднимается командой из авторской заметки ниже.

## Выдать участникам

Только `tar.gz` из [public/](public/) — внутри один файл состояния цепочки
(`luckyspire.state.json`), больше ничего. В условии — сюжет, адрес казино
(`0xe7f1725E7734CE288F8367e1Bb143E90bb3F0512`) и формат флага. Инструкций по запуску ноды
в условии НЕТ намеренно: участники/агенты сами разбираются, как подступиться к архиву
(на какой форк поднимать, как смотреть историю по блокам). Адрес CHIP тоже не даём —
токен ищется по трафику. Игровые контракты «чистые» при инспекции — это намеренно.

> Для справки автору: архив поднимается так (участникам НЕ выдаётся) —
> `anvil --hardfork shanghai --preserve-historical-states --state luckyspire.state.json`.
> Форк обязательно `shanghai` (pre-Cancun), иначе EIP-6780 ломает трюк.

## Идея

Казино делает `delegatecall` в settlement-движок по фиксированному адресу `H` (это первый
`CREATE` хаба, nonce 1). Инсайдер-оператор сносит движок и хаб, респавнит хаб через CREATE2
(тот же адрес → сброс nonce), затем обычный `deployGame(riggedCode)` попадает на `H`.
Раскладка хранилища rigged-движка **коллизит** со слотом доверенного оракула казино (slot 2),
поэтому рядовой расчёт ставки перенаправляет оракул на подставной адрес, который форсит
выигрыши ~10 несвязанным «дренерам». После каждого из 3 окон честный движок восстанавливается.

Никакого сломанного ГСЧ и украденного секрета — только коллизия раскладки хранилища через
delegatecall, протащенная метаморфным ре-деплоем на «неизменяемый» адрес `H`.

## Решение

1. Деньги утекают к ~10 несвязанным «удачливым» аккаунтам; контракты чистые — тупик.
2. Сгруппировать `BetSettled` по отправителю `fulfillRandomness`. Три легитимных оракула
   (ставятся через `rotateOracle`) + **4-й адрес**, который никогда не ставился через
   `rotateOracle`, но в трёх коротких окнах обслуживал ставки. (Он фулфилит и часть честных
   ставок обычных игроков — чтобы не торчать 100%-винрейтом.)
3. Слот оракула менялся **без** вызова `rotateOracle` → его переписал delegatecall-движок.
4. `eth_getCode(H)` по истории: codehash **меняется и откатывается** → `H` метаморфный.
5. `H` пересоздаётся только через destroy+respawn хаба (сброс nonce) и обобщённый
   `deployGame`, попадающий на nonce 1 == `H`. Отправитель этих ре-минтов — **инсайдер**.
6. Rigged-движок = честный + «jackpot promo», но его slot 2 алиасит `oracle` казино.
7. Дренеры vs шум: дренер **никогда не проигрывает** подставному оракулу (атакующий грайндит
   выигрышное слово), у честных игроков под тем же оракулом исход смешанный.

Готовый решатель: [solve/solve.py](solve/solve.py) (только публичные данные).
Подробный разбор: [solve/WRITEUP.md](solve/WRITEUP.md).

## Флаг

`ctfcup{keccak256("A+B+C+D")[:16 байт]}` — конкатенация hex-**строк** (без `0x`, нижний регистр):
`A`(40 hex)=подставной оракул, `B`(40)=инсайдер, `C`(64)=слот коллизии (2 как uint256),
`D`(64)=codehash rigged-движка. Хешируется ТЕКСТ склеенной hex-строки (208 символов), НЕ
упакованные байты. Первые 16 байт → 32 hex. Формат сдачи: `ctfcup{<32 hex в нижнем регистре>}`.

Считается **офчейн** игроком из восстановленных значений (на чейне ничего не хранит и не
проверяет — иначе реверс выдал бы ответ). В условии рецепт дан нейтральными формулировками
(«адрес, извлёкший выгоду из сбоя, но так и не получивший роль…»), которые бессмысленны без
решения. Эталонный расчёт: [deploy/flag.py](deploy/flag.py).

> `D` (а значит и значение флага) зависит от сборки контрактов. После любой перегенерации
> цепочки прогнать `deploy/flag.py` и обновить flag.
