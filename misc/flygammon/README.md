# Ровный робот | misc

**Автор:** [@x3lfyn](https://t.me/x3lfyn)

## Описание

Блокчейн-таск средне-высокой сложности: нужно обыграть ончейн-бота в нарды («плодовую
мушку») **20 партий подряд**, чтобы получить флаг. Контракты честные, кости — VRF с
доказательством, проверяемым ончейн. Но у группы VRF **гладкий порядок**, поэтому игрок
может восстановить секретный ключ оракула атакой на дискретный логарифм
(Pohlig–Hellman) и предсказать каждый бросок. Зная кости заранее, игра становится
детерминированной, и «непобедимая» мушка, оптимальная по матожиданию, обыгрывается.

## Деплой

## Структура

```
compose.yaml                 деплой: сборка образа из исходников и запуск
flygammon-handout.tgz        раздатка для участников
challenge/
    Dockerfile               образ таска (контекст сборки — папка таска)
    entrypoint.sh            подготовка инстанса (параметры, ключи, anvil, деплой, daemon, proxy)
    project/                 Foundry-проект — ончейн-лига
        src/Engine.sol       движок нард и валидатор ходов (key-native, с мемоизацией)
        src/VRF.sol          ончейн-верификатор Chaum–Pedersen DLEQ (слабый VRF)
        src/Flygammon.sol    стейт-машина игры, серия побед, бюджет коммитов, isSolved()
        script/Deploy.s.sol
        test/                тесты (движок + VRF)
flygammon/                   Rust-крейт модели: движок, фичи, сеть, тренер, чекпоинты в `attempts/`
                             (в образе используется h80_i100_distill/flygammon_best.mpk)
daemon/                      Rust-сервисы (alloy): `flygammon-daemon` — оракул мушки, который
                             публикует кости с доказательством и играет 2-ply ходы;
                             `flygammon-proxy` (src/bin/) — асинхронная единая точка входа:
                             whitelist RPC + info + флаг
solve/                       авторское решение на Python (DLP + игра со знанием костей)
tools/                       dlp.py, gen_params.py, make_instance_params.py, e2e.py,
                             instance_local.py
handout/                     то, что получает участник (README, исходники контрактов, веса .fly,
                             урезанные исходники модели, standalone oracle-daemon)
```

## Сборка и запуск инстанса (Docker)

```
docker compose up --build
curl -s http://127.0.0.1:8545/        # RPC, ключ игрока, адрес контракта, цель
curl -s http://127.0.0.1:8545/flag    # флаг после isSolved()
```

Всё работает на одном порту `:8545`, JSON-RPC (POST) для cast/web3 — на
`http://127.0.0.1:8545`.

При каждом запуске инстанс генерирует свежие параметры VRF и случайный ключ оракула.
Секрет оракула не попадает ни в цепочку, ни в RPC для игрока: RPC проксируется, чит-методы
anvil/evm заблокированы. На платформе настоящий флаг записывается в `/flag.txt`,
переменная `FLAG` — только локальный фолбэк.

## Решение и локальный end-to-end

```
python3 tools/e2e.py 20 60 40             # N=20, budget=60, factor_bits=40: anvil + деплой + daemon + решение
python3 tools/instance_local.py 2 12 24   # проверка инфраструктуры через rpc_proxy (без Docker)
```

При `factor_bits` около 40 дискретный логарифм на чистом Python считается примерно 10 секунд;
для быстрых итераций можно уменьшить.

## Параметры сложности

- `WIN_N` (в проде 20) — сколько побед подряд нужно для флага.
- `COMMIT_BUDGET` (в проде 60) — токены лиги, по одному на каждую закоммиченную партию.
- `FACTOR_BITS` (в проде 40) — самый большой простой делитель `p-1`, задаёт стоимость DLP.
- Сила мушки: 2-ply (`daemon`), честная, без слепых зон.

## Флаг

Кладётся платформой в `/flag.txt` при деплое.
