## Идея

Задание на реверс гипервизора. Программа защищена VMProtect в местах для усложнения статического реверса, из-за чего требуется динамика и трейсы чтобы дойти до кода проверки, сам код проверки защищён лишь кастомным протектором, который использует гипервизор, рантайм-значения Windows, а также обычные техники типа junk code + MBA для обфускации логики.

## Решение

Разбор стоит начать с того что кусается меньше - гипервизор. В нём нет никаких защит, он даёт разнообразные интерфейсы взаимодействия для клиентского бинарника, содержит внутри себя ARM64-подобный интерпретатор инструкций из клиента, хандлит cpuid/hypercall'ы и прочее. Отсюда понятно что стоит идти в клиентский бинарь.

Сам клиентский бинарь сильно запротекчен и в протекте используется как привязка к рантайм-значениям типа KUSER/TLS/ProcessId и так далее для обфускации immediate значений, так и различные другие техники. Изначально проанализировать без запуска его представляется невозможным, стоит запустить и дампнуть любым доступным способом, после фикса дампнутого PE'шника надо затрейсить где происходит логика проверки. Для трейса лучше всего попытаться обойти проверки дебага клиента из ядра, либо снимать трейсы с самого гипервизора. Сам гипервизор хорошая точка для трассировки, если снять трейс до нажатия на CHECK и после, а потом диффнуть получившееся - можно найти участки кода которые вызываются сугубо при нажатии на CHECK, далее методом исключения дойти до точки, в которую попадаем конкретно после нажатия на CHECK.

Сама внутренняя функция сильно обфусцирована не только через мутацию кода, MBA и гипервизор но и movfuscator-подобной защитой, где часть mov'ов заменены в эквивалентные инструкции через xor и другие битовые операции. Стоит сначала слифтить протектор используя динамику + тулзы типа [Mergen](https://github.com/NaC-L/Mergen), затем получив movfuscator-подобный код заменить все эквивалентные инструкции обратно в mov, а далее слифтить уже оставшийся код, для помощи используя сурсы оригинального movfuscator (данный слой намеренно приближен к movfuscator чтобы кросс-референс с сурсами был не таким болезненным).

Сама программа расширяет введённый буффер, а затем использует несколько разных кастомных хэшей, затем сравнивает их с эталоном. Достаточно восстановить код, сверить что восстановленная модель совпадает с клиентской через динамику, затем решить модель используя Z3 + знания формата флага.
